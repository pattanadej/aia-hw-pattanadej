# แหล่งเอกสารและวิธีหา (ใช้ตอนขั้น 2ก)

ไฟล์นี้บอกว่าจะไปหาเอกสารที่ไหนและระวังอะไร **ไม่ใช่การอนุญาตให้โหลด** — อนุญาตมาจากผู้ใช้ในแต่ละรอบตามนโยบายใน `SKILL.md`

## โดเมนที่โหลดได้ (เมื่อผู้ใช้อนุญาตแล้ว)

`set.or.th` · `setgroup.or.th` · `setlink.set.or.th` · `market.sec.or.th` · เว็บนักลงทุนสัมพันธ์ของบริษัทนั้น
โดเมนอื่น (เว็บข่าว โบรก YouTube ฯลฯ) → ถามผู้ใช้ก่อน และห้ามวิดีโอ/เสียง/แหล่งที่ต้องล็อกอินเสมอ

## ก.ล.ต. iDisc (เว็บทางการ เปิดสาธารณะ ไม่ต้องสมัคร)

รูปแบบลิงก์ (ตามที่ใช้ใน `/new-stock` ของโปรเจกต์นี้) แทน `<TICKER>` ด้วยตัวย่อที่ยืนยันแล้ว:

| เอกสาร | หน้ารายการ |
|---|---|
| งบการเงิน | `https://market.sec.or.th/public/idisc/en/Viewmore/fs-full?searchSymbol=<TICKER>` |
| 56-1 | `https://market.sec.or.th/public/idisc/en/Viewmore/fs-r561?searchSymbol=<TICKER>` |
| MD&A | `https://market.sec.or.th/public/idisc/en/Viewmore/fs-mda?searchSymbol=<TICKER>` |

- ไฟล์จริงอยู่ที่ลิงก์ `Download?FILEID=...` ในหน้ารายการ
- ต้องส่ง User-Agent แบบเบราว์เซอร์ + Referer = หน้ารายการของ iDisc ไม่งั้นถูกตัดการเชื่อมต่อ (Windows ใช้ PowerShell `Invoke-WebRequest` ได้)
- งบเป็น zip (Excel + Word) → แตกในโฟลเดอร์ชั่วคราวก่อน แล้วย้ายเข้าชั้นบนด้วยชื่อตามกติกา
- ถ้าลิงก์หรือโครงหน้าเปลี่ยน อย่าเดา URL ให้เปิดหน้าค้นหาของ iDisc แล้วดูลิงก์จริง

## SET: เอกสารประกอบ Oppday / Listed Company Presentation

- ค้นจากหน้าข้อมูลบริษัทหรือหน้า Listed Company Presentation บนเว็บ SET ว่ามีไฟล์สไลด์/เอกสารแนบของงวดที่ต้องการหรือไม่ (ตรวจ URL จริงในหน้า ห้ามเดา)
- Oppday ส่วนมากเป็นวิดีโอ ไม่มีไฟล์ → แจ้งผู้ใช้ ขอ transcript ที่ผู้ใช้เก็บไว้ ห้ามโหลดวิดีโอ ห้ามเดาเนื้อหา
- แผนระยะยาวหรือ guidance ที่บริษัทยื่น SET (ประกาศ/แบบนำเสนอ) ถ้าอยู่บนหน้าข่าวของ SET ถือเป็นแหล่ง A

## เอกสารหลายเวอร์ชันของงวดเดียวกัน

| เจอ | วิธีเลือก |
|---|---|
| Revised / แก้ไข | ใช้ฉบับแก้ไขล่าสุด บันทึกว่าฉบับก่อนมีตัวเลขต่างอย่างไรถ้าเห็น |
| Unreviewed / Reviewed / Audited | งบรายปีใช้ Audited · งบไตรมาสใช้ Reviewed ถ้ามี ไม่งั้น Unreviewed แล้วติดป้าย |
| งบรวม / งบเฉพาะกิจการ | ใช้งบรวมเป็นหลัก |
| ไทย / อังกฤษ | ใช้ฉบับที่อ่านตัวเลขได้ครบ ถ้าต่างกันให้บันทึกความต่าง |

ทุกครั้งที่เลือก ให้ลงในภาคผนวก ข: ฉบับที่ใช้ + เหตุผล

## เช็กลิสต์หลังโหลด

1. ชื่อบริษัทในหน้าแหล่งและในไฟล์ตรงกับหุ้นที่เลือก
2. ไฟล์เป็น PDF/ZIP จริง (ไม่ใช่หน้า error) เปิดได้ ขนาดสมเหตุสมผล
3. ZIP: ตรวจชื่อไฟล์ข้างในไม่มี `..` หรือ path เต็ม แตกในโฟลเดอร์ชั่วคราว ไม่รันไฟล์ที่ไม่ใช่เอกสาร
4. ชื่อไฟล์ปลายทางตามกติกา `YYYY-MM-DD_<ชนิด>_<งวด>` ชนกับไฟล์เดิม → ข้ามและแจ้งผู้ใช้
5. PDF ใหม่ → แปลงเป็น `.txt` คู่กัน
6. บันทึก URL · วันที่โหลด · ขนาด · เวอร์ชัน ลงภาคผนวก ข

## บรรทัด `.gitignore` ที่ควรเสนอให้ผู้ใช้ (ห้ามแก้เองโดยไม่ถาม)

เอกสารที่โหลดมาใช้วิเคราะห์ส่วนตัว ไม่ควรขึ้น repo ที่เป็นสาธารณะ:

```
ทุกบริษัท/
*.pdf
*.zip
*.xlsx
*.docx
```

ก่อนเสนอให้ตรวจ `.gitignore` ปัจจุบันว่ามีอยู่แล้วหรือไม่ และ repo เป็นแบบ private หรือ public (ผู้ใช้เป็นคนยืนยัน)
